# About the author

HabitForge is built and maintained by **Ahsan Mahmood**, a senior full-stack and mobile engineer. This page is the short version of who is behind the product and how to reach him.

## Who builds HabitForge

Ahsan is an independent engineer who designs, builds, and ships products end to end — from the data model and backend rules through the UI, the native mobile builds, and the browser extension. HabitForge is one of those products: a single-maintainer app that favors reliability and privacy over feature sprawl.

His engineering interests line up closely with how HabitForge is built:

- **Web and product engineering** with React, TypeScript, and modern build tooling.
- **Cross-platform mobile** with Capacitor, shipping the same codebase to iOS and Android.
- **Browser extensions** built to marketplace policy (the HabitForge extension uses the Chrome Identity API and bundles its analytics, with no remote scripts).
- **Pragmatic, zero-cost architecture** — leaning on free-tier infrastructure so a free product can stay genuinely free.

For the full technology credits behind HabitForge, see [Credits](./credits).

## Philosophy reflected in HabitForge

A few opinions show up directly in the product:

1. **Honest streaks.** The streak engine is forgiving of timezones and travel but does not silently inflate your numbers.
2. **Visualization over nagging.** The habit-strength meter makes progress legible at a glance; reminders are optional.
3. **Your data stays yours.** Manual export is always available, account deletion removes everything, and an optional Google Drive backup (using the narrow `drive.file` scope) keeps a copy in storage you control.
4. **Free, with no dark patterns.** HabitForge is zero-cost: no paid tier, no usage billing, and no third-party ad scripts — none at all in the browser extension.

## A note on the project structure

The HabitForge **app source is private**, but this **documentation site is public** and open. The public docs exist so that users, contributors, search engines, and AI assistants can discover and learn about the product even though the application code itself is closed. The documentation source is MIT-licensed.

If you are evaluating HabitForge, building something similar, or just curious about how a free, offline-first, cross-platform habit tracker is put together, the docs here are written to answer those questions honestly — including the product's limits.
